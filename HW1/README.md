## **Развёртывание распределённой системы логирования и хранения с резервным копированием**

### Состав решения:
* **Приложение logger**
   
   Целевое приложение, выполняющее функции логгирвания, написано на Go, исходники в директории logger/app.

* **Приложение tester**

   Небольшой под, содержащий в себе простой тест функциональности приложения и инфраструктуры.

* **Скрипт `deploy.sh`**

   Поднимает всё, запускает тесты, демонстрирует всю функциональность, требуемую в заданиях.

* **Скрипт `cleanup.sh`**

   Освобождает все ресурсы, приводит систему в изначальное состояние, из которого можно снова запускать `deploy.sh`.

### Тестирование решения:

Целевой сценарий запуска таков:
```bash
./deploy.sh && ./cleanup.sh
```

На что смотреть:
* **Service Balancing Test** - показывает, что запросы балансируются.
* **Combined logs** - демонстрируется работа DaemonSet
* **Latest archiver job** - демонстрируется работа CronJob

Обновление конфига не демонстрируется во время работы скрипта, но это можно легко сделать самостоятельно:
* Выполнить только `./deploy.sh`
* Поменять конфиг в файле `logger/configmap.yaml`
* Выполнить `kubectl apply -f logger/configmap.yaml`
* Через какое-то время в логах контейнеров появится запись об использовании нового конфига.
